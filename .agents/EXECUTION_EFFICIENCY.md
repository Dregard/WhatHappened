# Efficient discovery and verification
- Read root/index and selected domains once per task; reread only changed or missing context. Search paths/symbols first; read bounded ranges. Large output goes to a file with a concise summary/path; state truncation and read required continuations. Never omit error evidence.
- Use exact agreed decisions and prerequisite handoffs before asking repeated questions. Verify code/contracts against current source. Keep task boundaries explicit; do not absorb a later task's implementation into an earlier one.
- Reuse test evidence only with complete source/assets/dependency/config scope and matching environment/fingerprints. New runtime state, changed inputs or incomplete scope invalidates reuse. Keep final integrated acceptance. verification_ledger is optional: use it only for a small complete file scope already known. A miss, unsupported scope or error must not delay tests or cause a pause; run normal checks without caching. Do not enumerate whole directories, vendor SDKs or project dependencies merely to satisfy the ledger, and do not omit dependencies to fit its limit.
- Keep one Unity operation in flight. Recover the recorded result after a disconnect; never replay a mutation with unknown outcome. Avoid repeated model polling. Preserve unknown outcomes in the handoff.
- At coherent boundaries preserve a compact handoff: user decisions, changed paths/public contracts, remaining work, evidence and limitations. Do not replace original requirements with summaries. Never reset unfinished work just to satisfy a token threshold.
- Determine available shell/tools once; use native syntax. Keep disposable builds outside production assets and ordinary repository status output.

- An approval denial from optional Rider lint/semantic tooling is an availability warning. Do not retry it or change permissions; continue with available checks. Report unavailable required checks honestly. A denial from managed Unity MCP remains an infrastructure issue.
