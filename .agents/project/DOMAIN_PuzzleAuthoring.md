# Puzzle authoring

## Entry points and ownership
- `Assets/Game/Puzzles/Editor/PuzzleSlicerEditor.cs` remains the editor window opened by `Game/Puzzle Slicer Editor` and by `Assets/Game/Levels/Editor/LevelCreator.cs` through `GetWindow<PuzzleSlicerEditor>` and `SetPuzzleData`. Its original script GUID and window title are preserved.
- `Assets/Game/Puzzles/Editor/PuzzleSlicerSessionModel.cs` holds the selected data/texture, padded working image, manual contour, layers and visual selection. `Assets/Game/Puzzles/Editor/PuzzleSlicerSessionController.cs` owns pixel editing, reset, clear, layer restoration and data loading.
- `Assets/Game/Puzzles/Editor/PuzzleSlicerCanvasView.cs` owns pointer input, zoom/pan and anchor presentation. Its optional vertical-overhead argument reserves space for the window controls. `Assets/Game/Puzzles/Editor/PuzzleSlicerLayersView.cs` owns the layer panel; both share window-owned resources from `Assets/Game/Puzzles/Editor/PuzzleSlicerPreviewRenderer.cs`.
- `Assets/Game/Puzzles/Editor/PuzzleSlicerPersistenceController.cs` owns bake and level-wide rebake, delegates geometry, and saves the existing `Assets/Game/Puzzles/PuzzleData.cs` / `Assets/Game/Puzzles/PuzzlePieceData.cs` format. Editor classes remain in the existing predefined editor assembly; no runtime dependency on them was added.

## Shared formation path
- `Assets/Game/Puzzles/Editor/PuzzleSlicerSessionController.cs`: `AddSelection` removes the closing duplicate point and calls `AddPolygon`. `AddPolygon` accepts an owned list of points in padded texture coordinates, cuts pixels, appends a hidden selection and registers its cutting order. Generated AddMeshPolygon uses validated final fill-triangle samples instead of rounded pixel-space intersections, retaining the supplied shared contour. Batch generation and Load defer the working texture's GPU upload until all cuts finish; ordinary manual cuts upload immediately. Callers must provide a valid contour and initialized working texture; this path does not clear existing selections.
- `Assets/Game/Puzzles/Editor/PuzzleSlicerTextureUtility.cs` transfers the same covered pixel centers from the remaining RGBA32 working texture into an integer polygon-bounds crop with a one-pixel transparent sampling gutter (included in its budget); crop wrapping clamps to prevent preview edge bleed. `SelectionLayerData.rect` positions that crop in padded image coordinates. Cutting and restoration use borrowed `Color32` pixel views; working-image creation copies source bytes once without PNG round trips or full-size float buffers. Existing layers therefore retain ownership of overlaps, independently of later visual reordering. Restoration of deleted layers transfers only pixels with nonzero alpha; invisible RGB is not restored.
- `Assets/Game/Puzzles/Editor/PuzzlePieceMeshBuilder.cs` builds a mesh and returns its baked contour from an optional shared contour (analytic on fully visible rectangular sources, alpha-clipped otherwise), or from a layer's owned alpha pixels for manual/legacy layers. Crop origins are applied to extracted pixel contours before simplification; padded dimensions still determine centering and source UVs, preserving the full-size geometry result. It delegates contour extraction/simplification, triangulation and border/outline geometry to `Assets/Game/Puzzles/Editor/PuzzleTextureContourExtractor.cs`, `Assets/Game/Puzzles/Editor/PuzzleContourSimplifier.cs`, `Assets/Game/Puzzles/Editor/PuzzlePolygonGeometry.cs` and `Assets/Game/Puzzles/Editor/PuzzlePieceBorderBuilder.cs`.
- `Assets/Game/Puzzles/Editor/PuzzleBackgroundMeshBuilder.cs` creates silhouette fill, shared seams, outer border and per-piece highlight geometry from baked contours. These builders have no window dependency and do not write assets.

## Compatibility invariants
- Working textures retain 200 pixels of padding on each side. Piece and background UV0 map to the complete source texture, including transparent margins; tight sprite bounds must not replace that coordinate system.
- `Assets/Game/Puzzles/Editor/PuzzleSlicerCutOrderUtility.cs` persists cutting order in mesh UV7 and supports legacy trailing piece numbers and visual-index fallback. Loading recuts in ownership order while retaining saved visual order. Visual numbering and `LayerNumber` follow the list, not cutting order. Load multiplies unit contours as a Vector2 before adding the padded origin: rounding the scaled vector separately avoids Mono scalar-expression excess precision changing ownership at half-pixel boundaries.
- Piece border offsets use UV1 and shader colors; background line offsets use UV1 and highlight identifiers use UV6. Authored polygons, anchors, pivots, PPU lookup, mesh subassets and background naming remain part of the save contract.
- `Assets/Game/Puzzles/Editor/SelectionLayerData.cs` and `Assets/Game/Puzzles/PuzzlePieceData.cs` add optional shared mesh contours; missing legacy values retain independent pixel-contour extraction. Layer textures now use crops while authored polygons remain in padded coordinates; existing full-size in-memory layers have zero-origin rectangles and remain compatible. Canvas drawing, deletion restoration and BAKE/Load use crop origins. Source changes delegate to the same clear operation. Reset/clear/load and layer deletion release their retired transient textures; BAKE releases its temporary background-source texture. Generated markup supports layer visibility, rename, anchor, reorder, delete/re-add and BAKE/Load. BAKE preserves nonempty custom names in mesh names instead of renumbering them; LayerNumber still follows visual order. Optional HasAuthoringVisibility/AuthoringVisible fields in `Assets/Game/Puzzles/PuzzlePieceData.cs` restore preview visibility. Older puzzles without this marker load visible.

## Focused verification
Automatic generation checks are specified in [.agents/project/DOMAIN_PuzzleAutomaticSlicing.md](.agents/project/DOMAIN_PuzzleAutomaticSlicing.md).

For manual slicing compatibility, compare identical manual contours using sources with alpha margins and both texture-only and sprite imports. Check overlap/reorder behavior, anchors, deletion/clear, meshes and UV channels, save/load and legacy UV7 fallback. Level-wide rebake writes all puzzle assets under `Assets/Game/Levels` and must not be invoked merely to verify an editor change.
