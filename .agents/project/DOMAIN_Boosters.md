# Anomaly boosters

## Ownership and wiring
- `Assets/Game/Boosters/BoosterSystem.cs` retains inventory, unlock grants, reward additions and usage analytics. `TryUse` validates unlock and effect availability before consuming stock. Empty stock leaves the effect unavailable to spending but allows the existing HUD purchase flow.
- `Assets/Game/Initialization/GameplayInstaller.cs` binds only `Assets/Game/Boosters/Compas/CompassBooster.cs` (Hint) and `Assets/Game/Boosters/FreezeTimer/FreezeTimerBooster.cs` (Photo). The MagicWand implementation and exclusive assets are removed. Its numeric enum value and unknown saved stock remain solely for profile compatibility.
- Serialized kinds deliberately remain `Compass = 3` and `FreezeTimer = 2` in `Assets/Game/Boosters/BoosterKind.cs`; string inventory keys and numeric unlock/reward identities are preserved. Existing stocks, initial grants, unlock levels, prices and reward amounts are reused. No profile migration or free photo resource was introduced.
- `Assets/Game/Boosters/Compas/CompassBoosterData.asset` and `Assets/Game/Boosters/FreezeTimer/FreezeTimerBoosterData.asset` supply updated names, descriptions and icons. Their existing price/reward references remain authoritative. `Assets/Game/Purchase/BoosterRewardProcessor.cs` and rewarded-ad acquisition in `Assets/Game/UI/Windows/BoosterWindow/BoosterWindowModelProcessor.cs` still replenish the same stock through `BoosterSystem.Add`.
- `Assets/Game/UI/Hud/BoosterButtonsController.cs` uses the two installed boosters, supplies their actual icons through `Assets/Game/UI/Hud/BoosterButtonView.cs` and tolerates surplus slots. The production HUD prefab now contains exactly two booster buttons. `Assets/Game/UI/Hud/HudModelProcessor.cs` applies the same availability/unlock gate before spending or opening the purchase window.

## Attempt state and presentation
- `Assets/Game/Anomalies/AnomalyBoosterController.cs` owns attempt-local target, expiry and photo-use state. It consumes the existing `Assets/Game/Anomalies/AnomalySearchSystem.cs` public state and never writes findings or unfinished-attempt data into a profile. `Assets/Game/Anomalies/AnomalySearchView.cs` creates it; `Assets/Game/Levels/AnomalyLevelController.cs` exposes it as `Boosters` for economy adapters.
- Hint selects one unfound current-stage anomaly. Before Ready, during pause/photo/transition, after every target has been found, or while a pointer is already active, hint spending is rejected. Invalid/missing finger configuration also preserves inventory. It does not automatically retarget a found anomaly for free.
- `Assets/Game/Anomalies/AnomalyHintData.cs` contains finger sprite, canvas size, normalized fingertip and pulse tuning; the existing `HintDuration` in `Assets/Game/Boosters/Compas/CompassBoosterData.cs` remains authoritative. Duration defaults to 30 active seconds. Finding the target clears it synchronously through search notifications; stage changes, completion and disposal also invalidate it.
- `Assets/Game/Anomalies/AnomalyBoosterView.cs` presents a passive finger anchored to the target rectangle center on the fitted original board. Pulse and expiry stop during external pause; the finger is hidden during pause/photo and its expiry is suspended by photo. It never intercepts board taps.
- Photo opens only through the booster, displays the original fitted to the full canvas with a black letterbox background, and blocks board input. A tap on the HUD thumbnail raises `AnomalySearchView.PhotoRequested` → `AnomalyLevelController.PhotoRequested` → `Assets/Game/UI/Hud/HudModelProcessor.cs`, which runs the same `UseBooster(FreezeTimer)` path as the HUD button (unlock/availability gate, purchase window on empty stock, spending). Each accepted open consumes one shared-stock item and one of exactly three uses across all stages of the attempt. Repeated presses while open are rejected before stock consumption.
- Photo view phases (`Assets/Game/Anomalies/AnomalyPhotoPhase.cs`, driven by `Assets/Game/Anomalies/AnomalyBoosterController.cs`, animated by `Assets/Game/Anomalies/AnomalyBoosterView.cs`): Opening (a runtime clone of the HUD thumbnail polaroid with its own frame flies from the thumbnail polaroid, hidden meanwhile, to the center and lands exactly on the authored `Original` rectangle; the old standalone card art in `BoosterPhoto` is hidden) → Showing (captions fade in, five-second countdown runs, tap closes early) → Closing (photo and captions return; taps ignored) → None. `IsPhotoOpen` stays true through Opening/Closing, so the board and level clock stay blocked until landing. Flight and caption fade durations are `BoosterPhotoFlightDuration`/`BoosterPhotoLabelsFadeDuration` in `Assets/Game/Anomalies/AnomalyPresentationData.cs`. The animation stops under external pause. The backdrop alpha never reaches zero, otherwise it would be culled and stop blocking taps.
- Photo lasts exactly five active seconds (counted only in Showing). The five-second duration and three-use limit are product constraints in `Assets/Game/Anomalies/AnomalyBoosterController.cs`, not stage tuning. The old freeze-duration field was replaced with a read-only compatibility property in `Assets/Game/Boosters/FreezeTimer/FreezeTimerBoosterData.cs`; it returns five seconds.
- `Assets/Game/Levels/LevelController.cs` suspends countdown and active-attempt accumulation while photo is open without modifying gameplay pause or countdown-freeze flags. External pause stops photo expiry. Closing photo never releases another window/ad pause or independent freeze. Timeout/extra-time continuation keep the same attempt allowance; creating a new attempt creates a fresh controller and resets it.
- Disabling the search view disposes its booster state synchronously, clears pointer/photo and detaches search subscriptions before level assets are released. No delayed photo task can change another attempt.
