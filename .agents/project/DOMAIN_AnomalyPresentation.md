# Anomaly presentation

## Ownership and setup
- `Assets/Game/Anomalies/AnomalySearchView.cs` owns UI presentation on the existing level canvas. It creates a fitted main image with child anomaly layers, an upper-right passive original thumbnail, a closed HUD row sized to the actual selected stage, bottom finding text, and a fullscreen shutter/blackout graphic. Existing level scenes/prefabs are not rewritten.
- `Assets/Game/Anomalies/AnomalyLevelData.cs` retains serialized `FindingDuration` as outline duration and `TransitionDuration` as the duration of each transition fade. Its `Presentation` field embeds `Assets/Game/Anomalies/AnomalyPresentationData.cs`: photo/fade/flight/star/miss/blackout timing, flicker count, marker/star/cross appearance, thumbnail bounds, and shared audio IDs. `Assets/Game/Levels/Editor/AnomalyLevelEditorWindow.cs` exposes the nested tuning. Existing level fields/GUIDs remain intact.
- `Assets/Game/Anomalies/AnomalyUi.cs` creates passive Images/text and maps shared RectTransform geometry. `Assets/Game/Anomalies/AnomalyMarkerGraphic.cs` builds the progressively drawn uneven brush stroke (Perlin-wobbled ellipse path, variable thickness, rough edges, tapered brush head; per-instance random seed; shared brush shape settings `BrushThicknessVariation`/`BrushSizeScale` live in `Assets/Game/Anomalies/Theme/Resources/UiThemeData.asset`, only color/width stay per level; `Progress` is still the 0..1 outline-duration fraction). `Assets/Game/Anomalies/AnomalyFindingEffects.cs` owns finding/miss animation mechanics; its clocks consume the search pause flag.
- `Assets/Game/Levels/AnomalyLevelController.cs` forwards view `SfxRequested` through an injected callback. `Assets/Game/Levels/LevelController.cs` supplies the existing `Assets/Game/SFX/AudioSystem.cs`, preserving user SFX volume. The level adapter tracks emitted IDs and synchronously calls the existing StopSfx callback during disposal, before a replacement attempt starts. Defaults reuse configured `GlassSnap` and `ButtonClick` IDs; no separate AudioSource/service is introduced.

## Draw order
- `Assets/Game/Levels/LevelController.cs` passes the injected HUD canvas (`Assets/Game/UI/Hud/HudView.cs` `HudCanvas`) to the view; the old level canvas (no camera, thus overlay above everything) is only a fallback when no HUD is injected. The view root has no Canvas: thumbnail, slots, status/finding text, effects, shutter/blackout and booster photo are plain HUD-level children, so windows (separate `Windows` sorting layer) cover them like the rest of HUD.
- The `Board` child owns a nested override-sorting Canvas with GraphicRaycaster at HUD sorting order −1: field image, anomaly layers, markers, stars, hint finger and miss cross draw under HUD and windows. The finding/photo flights live at HUD level above the board. Hit conversion still uses the fitted `Original` rectangle; HUD/window graphics above it win the raycast.

## Timing and input invariants
- `Assets/Game/Anomalies/AnomalyBoardFrame.cs` (on prefab `BoardArea`) resizes the decorative `BoardFrame` to the fitted `Original` picture rectangle plus authored border padding (30/39/32/24 left/bottom/right/top: slightly under the ring's inner edge so no gaps show; the frame sibling draws above `BoardArea` with `FillCenter` off, so the ring hides the square picture corners); `AnomalySearchView` calls `Fit()` after setting the photo aspect, and the component refits on area resize. The frame is decoration only: hit conversion, markers and effects still use `Original`. Test: `BoardFrameFollowsFittedPicture` in `Assets/Game/Anomalies/Tests/PlayMode/AnomalyPresentationTests.cs` (managed run outcome unknown at authoring time).
- Ready hides immediately and rejects duplicate taps. The original flies into the thumbnail through a white shutter flash, already inside a clone of the Polaroid frame (`PhotoFrameFlight`, built by `AnomalySearchView.CreateFramedFlight`): the frame is scaled so its fitted photo equals the board rectangle at start, and position/scale/rotation interpolate to the real Polaroid's exact rectangle and angle; `FitFrameToPhoto` first resizes the Polaroid inside its authored slot as a 9-slice (window aspect equals the photo's, no gaps) and draws the frame graphic as a child above the photo; stage 0 anomaly layers are built before the flight, so they are in place when the frame leaves; the real Polaroid is activated only on arrival, replacing the clone without a jump. Only after that sequence does `Ready` invoke the controller and `AnomalySearchSystem.Start()`, enabling search and the shared clock. The thumbnail itself has no click action; enlarged comparison is owned by the photo booster; see [.agents/project/DOMAIN_Boosters.md](.agents/project/DOMAIN_Boosters.md).
- Each `Found` event immediately displays its authored HUD text and SFX, then starts its own coroutine. Other findings remain accepted. The marker draws for `FindingDuration`; only afterward do the layer fade and HUD flight begin. Stars spread/fade concurrently from the initial finding. A closed slot receives the found sprite and hides its cover only at flight arrival. `CompleteFinding(id)` runs after outline, fade, flight and stars have all finished.
- The "Yep!" text and the miss cross share `AnomalyFindingEffects.Popup`: spawn at the tap point (root-local, converted by `ToRootLocal`; findings fall back to the anomaly center when no tap exists), fade from zero alpha with a bouncing scale to 1 over `PopupAppearDuration` while flying up `PopupFlyDistance` in `PopupFlyDuration` (capped at 80% of appear), hold `PopupHoldDuration` (0.35 s), then fade to zero alpha and scale `PopupEndScale` (0.6) over `PopupDisappearDuration`. All popup values (plus `FindingTextSize`, `MissSize`, `MissColor`) live in the shared `Assets/Game/Anomalies/Theme/Resources/UiThemeData.asset`, not in per-level data; the popup runs on the pause-aware clock, does not gate `CompleteFinding`, and stops with the hierarchy. `MissDuration` was removed.
- Completion waits for every accepted finding acknowledgement. While the model remains at the completed old stage with `IsTransitionPending`, the view flickers to opaque black, renders at least one opaque frame, replaces field layers and HUD with the planned next stage, holds black, and fades in. Only after fade-in does `CompleteTransition(oldStage)` activate next-stage input or final completion. Empty stages use this same finite sequence.
- Board input accepts only the fitted main Image as the actual raycast target. Overlay sprites, animation graphics and text are passive. UI targets, letterboxing, pause/preview/transition taps are excluded. Screen-to-local conversion and normalized child anchors use the same fitted rectangle; transparent sprite pixels remain part of the rectangular hit area. A genuine miss displays a red cross at the local pointer position; retapping a found rectangle has no feedback or second credit.
- Unload/restart disables and destroys the whole owned UI before image release. `OnDisable` stops coroutines and detaches model subscriptions immediately. No delayed tween/global callback or runtime-created texture survives into another attempt. All effects are hierarchy-owned.
