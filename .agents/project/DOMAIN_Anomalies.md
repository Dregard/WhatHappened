# Anomaly search

## Ownership and setup
- `Assets/Game/Anomalies/` owns search configuration, pure attempt state, selection and the basic UI presentation. Its `Game.Anomalies` assembly depends on Unity UI and TextMesh Pro; it does not depend on puzzle, profile, loading or progression implementations.
- `Assets/Game/Levels/LevelData.cs` embeds `SearchData` (`Assets/Game/Anomalies/AnomalyLevelData.cs`). `MainImage` is required for every playable level. Optional `OriginalImage` is the original photo when it differs from the search field (objects present only in the original, e.g. a standing sign that later disappears for good): it is shown on the board before Ready, in the photo flight, thumbnail and photo booster; when the photo flies away the board switches to `MainImage`. Empty falls back to `MainImage` (`AnomalyLevelData.PhotoImage`). `ClueImage` is exposed through `Assets/Game/Levels/AnomalyLevelController.cs` for clue collection through [.agents/project/DOMAIN_Chapters.md](.agents/project/DOMAIN_Chapters.md). Existing level addresses, loading/release ownership and `LevelTime` remain authoritative.
- `Assets/Game/Gameplay/LevelsManager.cs` initializes only anomaly search and rejects missing `SearchData.MainImage`. Puzzle runtime/content and its fallback were removed; production anomaly/chapter content must be authored explicitly. `Assets/Game/Levels/Editor/LevelCreator.cs` creates a level with embedded search configuration, preserves remote registration and opens `Assets/Game/Levels/Editor/AnomalyLevelEditorWindow.cs`. It does not create puzzle data or open the slicer.
- `Assets/Game/Levels/LevelController.cs` owns the shared attempt clock, pause, timeout and time continuation. It owns/disposes `Assets/Game/Levels/AnomalyLevelController.cs`, which adapts search completion to `Assets/Game/Levels/LevelProgressController.cs`. Search attempts do not require `PuzzleData` and their victory snapshot does not read puzzle pieces or combos.

## Configuration and selection
- `Assets/Game/Anomalies/AnomalyData.cs`: unique case-sensitive ID, sprite, normalized rectangle relative to the main image (bottom-left origin), HUD text. Full sprite rectangles determine overlap and hits, including transparent pixels. Touching edges are permitted; positive-area intersections are not.
- `Assets/Game/Anomalies/AnomalyStageData.cs`: requested count and optional slot IDs. Missing/whitespace IDs are random. Extra IDs beyond Count do not create extra slots. Explicit assignments are processed before random slots and reserved across the entire attempt, so earlier random slots cannot consume a later authored ID.
- `Assets/Game/Anomalies/AnomalyStageSelectionController.cs` plans every stage once per attempt. IDs never repeat; unused entries need not appear. Random candidates are shuffled and searched for a largest non-overlapping subset up to the request, preserving accepted explicit assignments. Explicit conflicts/missing/reused IDs omit that authored slot with warnings; they are not silently replaced by random entries. Earlier conflicting explicit IDs take precedence.
- Invalid images, IDs or normalized rectangles are excluded with warnings. Insufficient candidates shrink the actual stage count. The inspector `Assets/Game/Levels/Editor/LevelDataEditor.cs` validates with a stable seed and displays warnings; runtime selection also publishes/logs its warnings. Inspector sampling is not proof that every random seed yields identical later-stage counts.

## Whole-image authoring
- `Assets/Game/Levels/Editor/AnomalyLevelEditorWindow.cs` opens from Game/Create Level, double-clicking a level asset, or the inspector button in `Assets/Game/Levels/Editor/LevelDataEditor.cs`. It edits the existing embedded search format; no separate search asset or puzzle data is required. Main/clue sprites, arbitrary anomaly layers, IDs, HUD text, normalized Bounds, ordered stages/slot IDs and presentation durations are serialized directly on the level. Save Level persists the asset; Unity Undo handles property edits and each image drag.
- `Assets/Game/Levels/Editor/AnomalyImagePreview.cs` fits the main sprite aspect and draws full rectangular layers. Dragging inverts editor y into the runtime bottom-left coordinates without pixel rounding. Numeric Bounds permit exact position/size edits. Sprite padding and atlas UVs match simple runtime UI Images; hit/overlap bounds still include transparent pixels.
- `Assets/Game/Levels/Editor/AnomalyAuthoringValidation.cs` reports duplicate/empty IDs, missing references even beyond Count, ignored extra slots, repeated explicit assignments, absent images/stages and total ID shortages. The window additionally uses the actual runtime selector with an editable preview seed to show stage shortages including previous stages and future explicit reservations. All-layers mode is composition; stage mode shows the actual seed-specific selection. Warnings never rewrite Count, IDs or geometry. A single seed is not a proof over all possible random outcomes.
- Disposable local checks passed 16 assertions for saved/reimported images, fractional Bounds, Unicode text and stages; reopening; actual IMGUI drag/Undo; game RectTransform agreement; warnings without mutation; and Addressables ScriptableObject resolution by the created key using the AssetDatabase provider. Remote bundles/downloads were not exercised by this editor check.

## Runtime and presentation contract
- `Assets/Game/Anomalies/AnomalySearchSystem.cs` exposes `Stages`, `CurrentAnomalies`, `StageIndex`, `IsFound(id)`, `IsStageFound`, `IsTransitionPending`, `IsCompleted`, warnings and events. State is attempt-local; nothing writes unfinished stage/findings to the profile.
- `Start()` enables search after Ready's photograph animation. Before it, the view displays only the original image and taps cannot find anomalies. `TryFind(normalizedPoint)` accepts a previously unfound active rectangle only while searching and unpaused. `Found` is raised immediately, so findings may animate concurrently without blocking other hits.
- Presentation must acknowledge each accepted finding with `CompleteFinding(id)`; only when every finding is acknowledged does the stage enter its transition gate. `CompleteTransition(stageIndex)` releases that gate, activates the next stage or publishes final completion. Stale and duplicate acknowledgements cannot advance twice. Empty stages and even an empty stage list use the same finite gate.
- `Assets/Game/Anomalies/AnomalySearchView.cs` owns photo, field/HUD, findings and blackout presentation. Read [.agents/project/DOMAIN_AnomalyPresentation.md](.agents/project/DOMAIN_AnomalyPresentation.md) when changing their timing, layout, input, audio or cancellation. Hint/photo state and economy integration are described in [.agents/project/DOMAIN_Boosters.md](.agents/project/DOMAIN_Boosters.md).
- After the Ready photograph finishes, active search ticks the existing timer. During fully found-stage presentation the countdown is suspended; the attempt is completed only after the final transition releases shared progress. Timeout pauses search; the existing extra-time purchase handler restores the same search and accumulated findings. Window pauses remain authoritative.
- Unload disables/destroys the owned view, cancels its coroutines, detaches completion subscriptions and drops the model before Addressables release.
