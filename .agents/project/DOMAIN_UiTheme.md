# UI theme and mockup screens

## Ownership
- `Assets/Game/Anomalies/Theme/UiThemeData.cs` holds every mockup sprite, the font and text/veil colors. The asset is `Assets/Game/Anomalies/Theme/Resources/UiThemeData.asset`, loaded through `UiThemeData.LoadOrDefault()`. Art copies live in `Assets/Game/Anomalies/Theme/Art/`; `Assets/TempAssets/` is only the delivered import source.
- `Assets/Game/UI/Editor/UiThemeBuilder.cs` (menu `Game/UI/Build Theme Data`) copies art, sets sprite import/nine-slice borders and fills the theme. Rerun it after adding art.
- `Assets/Game/Anomalies/Theme/UiKit.cs` positions themed primitives in 1080x1920 mockup pixels (origin top-left) as normalized anchors. The layouts below were baked from it into prefabs; at runtime only `Place`/`PlaceIn`/`MarkFound` are used for data-sized content. The delivered art carries transparent shadow margins: `PlacePadded` with `BodyPad`, `FramePad`, `ButtonPad`, `RibbonPad` keeps the visible edge on the mockup rectangle.
- Themed TMP text uses shared material assets in `Assets/Game/UI/Materials/` (outline per style). Never set TMP outline in edit mode on a prefab text: it creates an unsaved material instance.
- A Canvas that is the root of its prefab does not keep `overrideSorting` when built in edit mode; set sorting overrides in code at runtime (`AnomalySearchView.Initialize` does this for the board canvas).
- No notepad icon was delivered: `ClueCounterIcon` stays empty until art exists. `Daily_Btn.png` is not imported. The mockup banner placeholder is not drawn; the real banner is owned by the Ads domain.

## Screens (all layout lives in prefabs; code fills data, handles actions and visibility)
- HUD: there is one HUD, `Assets/Game/UI/Hud/HudView.prefab`. Its existing elements carry the themed look: `BoosterButton1` (Hint, first installed booster) and `BoosterButton2` (Photo, shown only after the search starts via `HudView._searchGatedBoosterWidget`) are `BoosterButtonView`s; the theme icon child is named `ThemeIcon` so `BoosterButtonView.SetPresentation` does not overwrite it with the booster data icon; their `LockedContainer` is disabled in the prefab and themed; `GoldCounter` is the existing `CurrencyCounter` with auto-update on. They sit directly under the HUD root; `TopGradient` (with timer, pause and legacy level text) stays disabled in the prefab. An empty stock shows `+` (existing `BoosterButtonView` behavior). `HudView._chapterHud` is a nested instance of `Assets/Game/Gameplay/Chapters/ChapterHud.prefab` (`ChapterHudView`: location title, evidence counter that opens the investigation), enabled by `ChapterSystem.Prepare` and hidden by `Cancel`.
- Search board: `Assets/Game/Anomalies/AnomalySearch.prefab` with `AnomalySearchView` (board, polaroid, plates, slots, start prompt) and `AnomalyBoosterView` (photo overlay, hint finger/ring). `AnomalySearchView.Create(canvas, prefab, data, search)` instantiates it on the HUD canvas; `LevelController._searchViewPrefab` holds the reference. Per-stage anomaly images and closed slots are cloned from `AnomalyStageImage.prefab` and `AnomalySlot.prefab`. Finding effects (marker, stars, flights, miss) in `AnomalyFindingEffects` stay procedural animation layers.
- **Result sequence is one window (supersedes the per-window description below).** `Assets/Game/Gameplay/Chapters/Windows/Result/ChapterResultWindow.prefab` (variant of `WindowBase`, class `ChapterResultWindow`, model `ChapterResultWindowModel`) stays open for the whole sequence and holds a persistent `Backdrop` plus stage panels (`ChapterResultStage` subclasses with a CanvasGroup: `ChapterEvidenceStage`, `ChapterLevelRewardStage`, `ChapterAllEvidencesStage`, `ChapterCulpritRevealStage`, `ChapterCulpritSceneStage`, `ChapterChapterRewardStage`). Ordinary level: evidence -> level reward; final level: evidence -> all evidences -> culprit reveal -> culprit scene -> chapter reward (no level reward). `ChapterResultWindow.Present` fades the previous stage out, prepares the next while transparent, fades it in (`LevelsData.ResultFadeSeconds`) and enables input only after the fade; each stage's `Play` ends on its button (NEXT/GET/tap) plus its exit animation, so repeated presses cannot skip stages (buttons are made non-interactive and WaitPress completes once). Evidence decoration fades out while the evidence flies into its slot; the clue is committed on landing; rewards are claimed once via the supplied callbacks. `ChapterSystem.RunResult` builds the model (restoration: no evidence stage when resuming a pending level reward or a completed chapter). Only `ChapterInvestigationWindow` remains a separate chapter window. Stage Veil images are disabled; the shared backdrop does the dimming. Elements used by several stages are not duplicated per stage: `ChapterResultShared` (`Shared` layer under the stages, plus `SharedFront` for the button) owns the evidence row, sunburst, logo, culprit contour/question and the single NEXT/GET button. Each stage exposes `Layout` (`ChapterSharedLayout`: mockup row layout and normalized anchors per element, null = hidden); on a transition `Exit` slides what stays (row slots, sunburst, logo, contour, button) and fades what leaves while the old stage fades out, and `Enter` fades in what is new while the next stage fades in. The level reward's icons/amounts fly out of the just-found evidence slot (`ChapterRewardStageBase.Intro`); on the reveal the contour circle hands over to the stage's ring/portrait. Per-stage anchors/row numbers are constants in the stage classes (taken from the mockup prefabs). Historical text below about separate windows describes layout only.
- Chapter screens (before merge) were separate windows under `Assets/Game/Gameplay/Chapters/Windows/`. Each is a prefab variant of `Assets/Game/UI/Windows/General/WindowBase.prefab` (default fade controller, Escape dismissal disabled) with its own window class and model, registered in `Assets/Game/UI/Windows/WindowsContainer.prefab`: `ChapterInvestigationWindow` (found evidence, opens from the HUD counter), `ChapterEvidenceWindow` (new evidence, NEXT, flight into its slot, commit), `ChapterLevelRewardWindow` and `ChapterRewardWindow` (both `ChapterRewardWindowBase`, differ by prefab layout), `ChapterAllEvidencesWindow` (convergence effect), `ChapterCulpritRevealWindow`, `ChapterCulpritSceneWindow`. `ChapterSystem` owns the sequence (evidence found -> level reward, or all evidences -> culprit reveal -> culprit scene -> chapter reward): it opens the next window before closing the previous one and calls `CloseWindows()` on continuation. Shared parts: `ChapterEvidenceRow` + `ChapterEvidenceSlot.prefab`, `ChapterSunburstSpinner`, generic `ChapterWindowModelProcessor<TModel>` (one binding per model in `GameplayInstaller`). The old `WinWindow` remains only for legacy non-chapter progression.
- Out-of-stock popup: `Assets/Game/UI/Windows/BoosterWindow/BoosterWindow.prefab` contains the themed `ThemedPopup`; `BoosterWindow.cs` fills texts/pack sprite and wires buy/ad/close (plain Buttons, no click SFX, as before).
- Booster unlock popup: `Assets/Game/UI/Windows/BoosterUnlockWindow/BoosterUnlockWindow.prefab` contains the same themed popup look (body, red ribbon, green "Great!" button); `BoosterUnlockWindow.cs` fills name, description and icon and routes OK. `BoosterData.Icon` of both boosters now points at the theme pack sprites (`HintPackIcon`, `CameraPackIcon`), the same art as the out-of-stock popup and level rewards; the HUD uses `ThemeIcon` children and is not overwritten.
- Photo stock is per level: `FreezeTimerBoosterData.PhotosPerLevel` refills it at each level start (`BoosterSystem.RefillPerLevelBoosters`); purchases add during the level and leftovers do not carry over.

- `ChapterEvidenceWindow` follows the 1080x2400 mockup `Assets/TempAssets/Previews/07_Win_Evidence_Found_1080x2400.png`: its prefab anchors are fractions of 2400 and its code constants (`MockupHeight` and neighbours) pass `referenceHeight` 2400 to `ChapterEvidenceRow.Build` / `ChapterEvidenceSlotView.Place`. Other chapter windows still use the 1920 layout.
- `ChapterLevelRewardWindow` follows `Assets/TempAssets/Previews/08_Win_Reward.png` (1080x1920). Reward icon/amount placement comes from `ChapterRewardWindowBase` serialized fields (`_rewardCenterY`, `_rewardMaxSize`, `_amountGap`, `_amountHeight`; defaults keep the `ChapterRewardWindow` layout). Level rewards currently authored are boosters only, so the mockup coin/`+200` is illustrative.

## Shared UI prefabs
- Every button (themed popups, chapter windows, HUD counter, search Ready prompt, invisible tap areas) is an instance of the project prefab `Assets/Game/UI/Buttons/Button.prefab` (`GameButtonWithText`: click SFX `ButtonClick`, `ButtonClickedSignal`, `SetInteractable`). Per instance: root anchors, `Background` sprite/type (stretched to the root), the `Text` child (renamed `Label`/`Price`/`Free`, or removed when unused) and extra children such as the coin or ads icon. Code uses `GameButton.ClickEvent`/`SetInteractable` (`ChapterButtonExtensions.WaitPress` takes a `GameButton`), never `Button.onClick`. `AnomalySearchView` is in the isolated `Game.Anomalies` assembly and cannot see `GameButton`, so its `_readyButton` is the Unity `Button` on the same prefab root; `AnomalyLevelController`/`LevelController` pass `DiContainer.InjectGameObject` to `AnomalySearchView.Create` so the `GameButton` is injected (a missing injection is tolerated by `GameButton` for isolated tests).
- `Assets/Game/UI/Windows/Elements/ThemedPlate.prefab`: sprite plate with a stretched `Label` TMP; instances are the red ribbons, narrative/task/chapter plates and the "ORIGINAL" tapes (sprite, anchors and text style are per-instance overrides).
- Add new themed buttons/plates as instances of these prefabs; change common behavior in the prefab.

## Authoring data
- `Assets/Game/Anomalies/AnomalyLevelData.cs`: `ClueImage` (evidence icon), `ClueName`, `IntroText`. `Assets/Game/Levels/ChapterData.cs`: `Title`, `LevelRewardsList`, `RewardsList`, culprit portrait/caption, scene image/caption. Amounts live only in assets; mockup numbers are illustrative. Result timings are in `Assets/Game/Levels/LevelsData.cs`.
- The final level of a chapter skips the level reward and goes to the culprit sequence; the chapter reward uses the existing claim flag.

## Visual verification
- The 1080x1920 mockups were compared with screenshots rendered from the production views with fake data (disposable harness, removed after use). Play mode freezes while the editor is unfocused unless `Application.runInBackground` is set, and `WaitForEndOfFrame` never fires then; render a camera into a RenderTexture instead. URP: render with a new base camera (the HUD camera is an overlay camera and renders nothing alone).
- Managed `run_tests` for PlayMode returned an unknown outcome three times (transport lost around the play-mode transition); results were not recovered. The prefab move was checked by compilation, an edit-mode scan of serialized references and an editor screenshot of the HUD; in-game visual parity of the chapter windows is still pending.
