# Generated puzzle geometry and persistence

Read for generated cutting, mesh formation, preview, ownership or BAKE/Load. Controls and construction: [.agents/project/DOMAIN_PuzzleAutomaticSlicing.md](.agents/project/DOMAIN_PuzzleAutomaticSlicing.md). Shared authoring: [.agents/project/DOMAIN_PuzzleAuthoring.md](.agents/project/DOMAIN_PuzzleAuthoring.md).
- `Assets/Game/Puzzles/Editor/PuzzleSlicerPixelMetric.cs` snapshots nonzero-alpha membership, including alpha 1/2, with row-prefix counts and signed path integrals. `Assets/Game/Puzzles/Editor/PuzzleSlicerTextureUtility.cs` preserves Color32 bytes, crop gutters and 200-pixel padding. Generated cuts use the actual float fill triangles: StageMeshPolygon in `Assets/Game/Puzzles/Editor/PuzzleSlicerGenerationController.cs` builds the mesh before AddMeshPolygon in `Assets/Game/Puzzles/Editor/PuzzleSlicerSessionController.cs` transfers samples. Pixel-space crossing rounding is not authoritative after float PPU conversion. Manual/legacy cuts retain their canonical pixel-space scanlines.
- Every piece must be nonempty and four-neighbor connected. `Assets/Game/Puzzles/Editor/PuzzleSlicerVisibleGeometryValidator.cs` validates actual fill-triangle ownership, triangle edge connectivity and visible alpha before and after cutting. ValidatePartition uses the same conversion, triangulation and fill checks before candidate selection, without constructing native Mesh objects; it also requires nonempty four-connected raster ownership and exclusive complete source coverage. Coverage is reused only inside the synchronous transaction; independent validation rerasterizes. Point contacts, border geometry and zero-area bridges do not connect visible components. `Assets/Game/Puzzles/Editor/PuzzleSlicerMeshContourBuilder.cs` retains cross-layer coverage checks.
- `Assets/Game/Puzzles/Editor/PuzzlePolygonGeometry.cs` uses double-precision orientation/containment, canonical scanlines and bounded ear clipping with an x index. Ears at repeated bridge vertices additionally reject diagonals crossing active edges; reversed final triangles are invalid. `Assets/Game/Puzzles/Editor/PuzzleSlicerHoleBridgeBuilder.cs` attaches clockwise holes through retraced zero-area bridges, considering all holes and the correct local interior sector. Invalid geometry is rejected.
- `Assets/Game/Puzzles/Editor/PuzzlePieceMeshBuilder.cs` resolves the same source sprite/PPU for preflight and BAKE. ToMeshPolygon owns the exact float coordinate conversion and winding used by both candidate validation and mesh construction. `Assets/Game/Puzzles/Editor/PuzzleSlicerCanvasView.cs`, `Assets/Game/Puzzles/Editor/PuzzlePieceBorderBuilder.cs` and `Assets/Game/Puzzles/Editor/PuzzleBackgroundMeshBuilder.cs` consume actual mesh contours; retraced bridges are omitted from outlines/highlights. Background exact shared-edge keys retain distinct short subpixel seams; legacy/manual paths keep their prior behavior.
- `Assets/Game/Puzzles/Editor/SelectionLayerData.cs` separates selection polygons from MeshPolygonPixelsList. `Assets/Game/Puzzles/Editor/PuzzleSlicerPersistenceController.cs` saves exact SelectionPolygonPixelsArray and MeshPolygonPixelsArray in `Assets/Game/Puzzles/PuzzlePieceData.cs`. `Assets/Game/Puzzles/Editor/PuzzleSlicerSessionController.cs` restores exact arrays and cutting order without PPU drift. Generated Load recuts from the saved mesh at the saved PPU and validates ownership/connectivity, preserving the same representation used before BAKE. Missing legacy arrays retain unit conversion, pixel-space cutting and old extraction. BAKE retains custom names in mesh names and stores preview visibility through HasAuthoringVisibility/AuthoringVisible; absent legacy visibility loads visible. Anchors, visual reorder, deletion/re-addition and repeated BAKE/Load remain shared with manual authoring.
