# Combat network invariants
Read when changing combat authority, attack effects/events, duplicate delivery, combat replay, pooling or death/restoration/travel admission.

- The server owns enemy AI, attack admission/execution, damage, death and rewards. Clients present admitted server results; range, chase eligibility and repeated IsAttacking samples must not create speculative combat effects.
- Give each concrete attack a positive AttackId scoped to attacker and combat lifetime. Generate a fresh lifetime on authority restoration/reuse. Keep consumption with the attacker, independent of a replaceable motion presenter; different attackers must not share one delivery cursor.
- Distinguish windup admission from strike execution. The existing melee outline represents the executed hit volume: publish and show it once when the server completes AttackDelay, alongside the hit query. Do not move damage earlier or change authored tuning to align presentation. Cancelled windup emits no strike effect.
- Verify each wire field with the installed generated serializers, including nonzero geometry. Do not assume Unity value types with private storage serialize correctly. EnemyStrikeBroadcast transmits Center/Size vectors and excludes its computed Bounds property with FishNet's ExcludeSerialization attribute; a duplicate serialized property must not overwrite those vectors.
- Reuse the installed FishNet-compatible delivery path. Inspect package version, actual manager/prefab settings and connected call sites before changing them; native prediction defaults do not establish typed-broadcast behavior.
- The host's local effect and server echo must share once-only semantics. Duplicate or repeated state delivery must not recreate a consumed effect. Motion binds current lifetime but never starts a combat effect.
- Reject mismatched run, location, world, recovery, travel and actor lifetime before presentation/commit. Early events may wait only for matching authoritative motion; clear pending events at world revision changes. Preserve an executed living strike for its authored duration through ordinary world/health snapshots; terminate visuals on death, changed combat lifetime, recovery, travel or lost combat readiness. Disable/death retires a lifetime; cached samples cannot reopen it. Ordinary living snapshots must preserve consumption without permanently retiring an unchanged authority lifetime.
- Replay reconstructs required simulation, including movement, collision, timers and rope state. It must not emit combat sound, particles, camera shake, UI, RPC, damage/death/reward commits or other irreversible effects again. Do not skip necessary simulation to suppress presentation.
- Reuse authenticated command consumption and durable reward receipts; duplicate delivery must not dispatch damage, death or awards twice. Recheck lifecycle/readiness after asynchronous waits before committing.
- Preserve authored combat/hook parameters, visuals and ownership. Keep optional diagnostics disabled by default and restricted to useful boundaries, with tick, role, replay state, attacker/lifetime, AttackId and decision; never add normal per-tick log spam.

## Diagnosis and evidence
Trace actual server admission -> delayed strike execution -> event identity/publication -> scope/lifetime admission -> duplicate cursor -> rendered effect. Separately inspect prediction replay, delayed callbacks and pooled reuse. Compare body/query/mesh frames before assigning an AI or transport cause. Distinguish source-confirmed mechanisms from reproduced symptoms.

Use focused socket-free checks for timing, duplicate states/events, replay/confirmation, independent attackers, new pooled lifetimes, stale events and once-only damage/death/rewards. Compilation and isolated checks do not prove multiplayer timing. Follow NETWORK_RULES.md for manual host/remote acceptance after walk/stop/jump/hook, restoration/travel and available latency/loss.
