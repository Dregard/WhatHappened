# Инструкция для ИИ геймдизайнера: уровни, главы, награды и запуск в Play Mode

Документ описывает фактический пайплайн проекта WhatHappened (Unity, Addressables, поиск аномалий на фотографии). Все пути указаны от корня Unity-проекта. Инструкция проверена по исходникам на момент написания; если в проекте что-то отличается — доверяйте текущему коду и сообщите о расхождении.

> Граница автоматизации. ИИ может: создавать и настраивать ассеты `LevelData`, регистрировать их в Addressables, править `LevelsData.asset`, запускать сборку и Play Mode. ИИ **не может**: придумывать изображения, названия, награды и границы глав; загружать собранные файлы на сервер; подтверждать, что сервер отдаёт файлы. Всё недостающее — запросить (раздел 2).

Не полагайтесь на то, что каталог пуст или заполнен. Перед работой откройте и прочитайте:

Не меняйте файлы `AGENTS.md` и `.agents/*.md`. Часть проектной документации в `.agents/project/` может отставать от кода (например, там написано, что каталог пуст, а `Level0` уже есть) — источник истины код и ассеты.

## 1. Общая схема пайплайна

1. Получить материалы и решения от геймдизайнера (раздел 2).
2. Импортировать изображения как **Sprite** в проект.
3. `Game/Create Level` → получить ассет уровня и окно редактора (раздел 3).
4. Назначить основное изображение, изображение улики, добавить аномалии, стадии, время, нажать **Save Level** (разделы 3–5).
5. Адрес уровня регистрируется в Addressables (группа `Levels`) автоматически — это **только делает уровень доступным для выбора** (раздел 6).
6. Добавить адрес уровня в `LevelsData.Levels` (каталог загрузки) **и** в нужную главу `ChaptersArray[i].LevelsArray` (раздел 6).
7. Настроить главы: порядок, награды, финал (раздел 7).
8. Проверить локально в Play Mode (раздел 9).
9. Для удалённой доставки: собрать контент, разместить файлы на сервере, проверить доступность (раздел 8). Это отдельная проверка.

Меню проекта:

| Меню | Что делает |
| --- | --- |
| `Game/Create Level` | Создаёт `LevelData`, регистрирует в Addressables, открывает окно **Anomaly Level** |
| `Game/Content/Configure Remote Levels` | Настраивает группы `Levels`/`Level Shared` для удалённой доставки, регистрирует **все** `LevelData` из `Assets/` |
| `Game/Content/Build Remote Levels` | Выполняет Configure, затем собирает Addressables-контент |
| `Game/Profile/Show` | Открывает папку сохранённого профиля игрока |
| `Game/Profile/Delete` | Удаляет папку профиля (сброс прогресса) |
| `Game/Profile/Apply From ...` | Подменяет профиль выбранным `.json` (не работает в Play Mode) |
| `Game/PlayerPrefs/Delete` | Очищает PlayerPrefs |

## 2. Исходные материалы и решения: что запросить, а не придумывать

### 2.1. Обязательно для каждого уровня

| Данные | Формат | Если нет |
| --- | --- | --- |
| Основное изображение (`MainImage`) — исходная сцена | Импортирован как Sprite (Texture Type = Sprite (2D and UI)) | Запросить. Без него уровень не загрузится (`Assign SearchData.MainImage before loading this anomaly level`) |
| Изображение улики (`ClueImage`) | Sprite | Запросить. Для уровней в главах обязательно |
| Список аномалий: для каждой — изображение-слой (Sprite), положение и размер на основном изображении, ID, текст для HUD | см. раздел 4 | Запросить положение/размер; не угадывать на глаз без согласования |
| Структура стадий: сколько стадий и сколько аномалий в каждой; какие аномалии закреплены за какой стадией, а какие случайные | см. раздел 5 | Запросить; в крайнем случае предложить вариант и пометить как предположение |

### 2.2. Решения геймдизайнера, которые нужно получить до настройки

- Список уровней и их порядок внутри каждой главы.
- Разбиение на главы (какие уровни в какой главе), порядок глав.
- Для каждой главы: награды за главу (`RewardsList`), награды после каждого не последнего уровня (`LevelRewardsList`), нужны ли заголовок локации, портрет и подпись виновного, картинка сцены виновного и её подпись.
- Для каждого уровня: время на уровень (`LevelTime`, 0 = без таймера), название улики (`ClueName`), вводный текст (`IntroText`).
- Какие именно награды (тип, валюта/бустер, количество) и какие готовые ассеты `RewardData` использовать или создавать.
- Какая ветка контента (`ContentBranch`) и платформа используются для удалённой сборки, и кто загружает файлы на сервер.

### 2.3. Правила

- Если отсутствуют изображения, количество/порядок уровней, награды, границы глав — **остановиться и задать вопросы** (структурированный список: что именно, зачем, варианты). Не создавать плейсхолдеры в производственных папках.
- Не придумывать числа координат аномалий без исходной разметки (пиксельные рамки от дизайнера или файл-референс).
- Любые допущения явно помечать в отчёте.

## 3. Создание уровня

1. Импортируйте спрайты (основное, улики, слои аномалий) в проект. Положите их в папку будущего уровня или другую согласованную; для слоёв аномалий можно использовать нарезанные спрайты (sub-sprites) из одной текстуры — так сделано в `Level0`.
2. Выполните меню **`Game/Create Level`**.
   - Создаётся папка `Assets/Game/Levels/LevelN/` и ассет `Assets/Game/Levels/LevelN/LevelN.asset`. `N` — первое свободное число (начиная с количества записей в группе `Levels`; занятые папки и адреса пропускаются).
   - Внутри вызывается `Configure Remote Levels`: уровень регистрируется в группе `Levels` с меткой `Level`, **адрес = имя ассета** (`LevelN`).
   - Ассет выбирается в Project, открывается окно **Anomaly Level**.
3. В окне **Anomaly Level** (слева — поля, справа — превью картинки с перетаскиванием слоёв):
   - Поле **Level** — редактируемый ассет `LevelData`.
   - **LevelTime** — время на уровень, секунды (целое). `0` — без таймера.
   - **MainImage** — основное изображение (обязательно).
   - **ClueImage** — улика (обязательно для уровней в главах).
   - Блок **Anomaly images**: кнопка **Add Anomaly** создаёт слой с `Bounds` = (0.4, 0.4, 0.2, 0.2) и пустыми ID/Image/HudText; кнопка **Remove** удаляет слой. Выбранный слой можно двигать мышью по превью, либо ввести числа в `Bounds`.
   - Блок **Stages (in play order)**: список `StagesList`.
   - `FindingDuration`, `TransitionDuration`, `Presentation` — настройки презентации (раздел 5.4).
   - Блок предупреждений: поле **Selection preview seed**, кнопка **Refresh Warnings**, выпадающий список **Preview** (все слои / конкретная стадия).
4. **Сохранение:** кнопка **Save Level** внизу левой панели (`ApplyModifiedProperties` + `SaveAssetIfDirty`). Без неё изменения могут остаться только в памяти. Дополнительно можно выбрать `File > Save Project`.
5. **Повторное открытие:** двойной клик по ассету `LevelN.asset`, или выбрать ассет и нажать **Open Anomaly Level Editor** в инспекторе, или поле **Level** в окне. Инспектор `LevelData` также показывает предупреждения валидации (с seed = 0).
6. После сохранения закройте/перезагрузите окно и убедитесь, что значения сохранились (картинки, ID, Bounds, Count стадий).

Нельзя: создавать уровни, копируя `Level0` вручную без проверки уникальности адреса. Уникальность адреса обязательна — `Configure` выбрасывает исключение при пустом или дублирующемся адресе.

## 4. Аномалии: параметры и геометрия

Поля `AnomalyData` (список `AnomaliesList`):

| Поле | Обязательно | Описание |
| --- | --- | --- |
| `Id` | Да | Строка, уникальная в пределах уровня, **с учётом регистра** (`Door` ≠ `door`). Пустой или повторный ID — слой исключается из выбора с предупреждением |
| `Image` | Да | Sprite слоя, накладываемый на основное изображение. Без него слой исключается |
| `Bounds` | Да | `Rect` (x, y, width, height) в нормализованных координатах основного изображения |
| `HudText` | Нет (рекомендуется) | Текст описания в HUD поиска. Пустой — без описания |

### 4.1. Нормализованные координаты

- Значения от 0 до 1 относительно **всего** основного изображения; ширина = 1 — вся ширина картинки.
- **Начало координат — левый нижний угол** изображения. `x`, `y` — левый нижний угол прямоугольника. В превью редактора ось Y инвертируется сама; при ручном вводе числа в `Bounds` считайте от нижнего края.
- Пересчёт из пикселей (точка (px, py) отсчитывается от левого верхнего угла картинки размером W×H, рамка pw×ph):
  - `x = px / W`
  - `y = 1 − (py + ph) / H`
  - `width = pw / W`
  - `height = ph / H`
- Допустимо: `x ≥ 0`, `y ≥ 0`, `x + width ≤ 1`, `y + height ≤ 1`, `width > 0`, `height > 0`, значения конечные (не NaN/Infinity). Иначе слой исключается с предупреждением `Bounds ... lie outside the normalized 0..1 image area` или `Bounds size must be positive`.
- Чтобы слой не растягивался, выбирайте `width/height`, соответствующие размеру слоя в пикселях относительно основного изображения (`pw / W`, `ph / H`).

### 4.2. Прозрачные пиксели и попадание

- Область нажатия и проверки пересечений — **весь прямоугольник `Bounds`, включая прозрачные пиксели спрайта**. Прозрачные поля слоя тоже засчитываются как попадание и участвуют в конфликтах пересечения. Обрезайте спрайты слоёв по видимому содержимому или задавайте `Bounds` по тому участку, который должен ловить нажатие.
- Рамки, которые лишь касаются краями (общая граница без положительной площади пересечения), **разрешены**. Пересечение с положительной площадью — конфликт.

### 4.3. Ограничения пересечений

В одну стадию случайный выбор не помещает аномалии с пересекающимися `Bounds`. Если дизайнер хочет, чтобы две близкие аномалии были в одном уровне, разнесите их по разным стадиям или оставьте пересечение и учтите, что они не будут активны одновременно.

## 5. Стадии и параметры уровня

### 5.1. `StagesList` (элемент `AnomalyStageData`)

| Поле | Обязательно | Единицы/значения | Влияние |
| --- | --- | --- | --- |
| `Count` | Да (для непустой стадии) | Целое ≥ 0 | Сколько аномалий нужно найти в стадии. `0` — пустая стадия (проходит только через презентационный переход). Если кандидатов не хватает, фактическое количество уменьшается с предупреждением |
| `AnomalyIdsList` | Нет | Список строк-ID по слотам | Слот i = i-я аномалия стадии. Пустая/пропущенная строка — случайный слот. Элементы за пределами `Count` не создают слотов (предупреждение `outside Count`) |

Порядок стадий в списке — порядок прохождения. Уровень завершается, когда найдены аномалии всех стадий. Пустой `StagesList` — уровень без слотов поиска (предупреждение `No stages configured`); для рабочего уровня нужна хотя бы одна стадия с `Count > 0`.

### 5.2. Явное и случайное назначение

- **Явное:** в слот записан ID. Явные назначения обрабатываются раньше случайных и **резервируются на весь уровень** — случайный слот более ранней стадии не может «забрать» ID, закреплённый за более поздней стадией.
- **Случайное:** слот пуст. Кандидаты перемешиваются, затем ищется наибольший набор непересекающихся аномалий до нужного количества. Результат зависит от seed попытки.
- ID не повторяются между стадиями и слотами: одна аномалия — максимум один раз за прохождение. Лишние (не использованные) аномалии в `AnomaliesList` допустимы.
- Суммарно `Count` по стадиям не должен превышать число уникальных валидных ID, иначе предупреждение `Stages request N anomalies in total, but only M unique IDs exist`.

### 5.3. Последствия конфликтов и предупреждения

| Ситуация | Что происходит |
| --- | --- |
| ID не найден / слой исключён как невалидный | Слот пропускается (не заменяется случайной аномалией) |
| ID уже использован раньше | Слот пропускается; побеждает более раннее назначение |
| Явный ID пересекается с уже выбранной аномалией стадии | Слот пропускается |
| Кандидатов для случайных слотов не хватает | Стадия содержит меньше аномалий, чем `Count` (`requested N, available M`) |
| Пустой ID / дубликат ID / нет Image / неверный Bounds | Слой исключается с предупреждением |

Предупреждения показываются в окне **Anomaly Level**, в инспекторе `LevelData` (seed 0) и пишутся в лог в рантайме. Редактор **ничего не исправляет сам** (не меняет `Count`, ID, геометрию). Предупреждения нужно устранить правкой данных.

**Ограничение проверки:** предпросмотр использует один seed. Стадия со случайными слотами может дать другой набор и даже другое число аномалий на другом seed. Проверьте несколько seed (поле **Selection preview seed**) и проектируйте так, чтобы нужное количество получалось при любом выборе; самый надёжный способ — явные ID для критичных слотов.

### 5.4. Параметры уровня и презентации

Уровень (`LevelData` / `AnomalyLevelData`):

| Поле | Обязательно | Единицы | Влияние |
| --- | --- | --- | --- |

Нулевые длительности допустимы, но делают эффект мгновенным.

## 6. Регистрация в Addressables и включение в прогрессию

Важное различие:

| Шаг | Что даёт | Чего НЕ даёт |
| --- | --- | --- |
| Регистрация адреса (группа `Levels`, метка `Level`, `IncludeAddressInCatalog`) | Уровень попадает в Addressables-каталог, появляется в выпадающем списке `LevelReference`, может собираться в бандлы | Не добавляет уровень в игру |
| Запись в `LevelsData.Levels` | Уровень попадает в каталог загрузки (`LevelsManager` грузит по `LevelId`; индекс нужен главам и туториалам) | Не задаёт порядок в главе |
| Запись в `ChaptersArray[i].LevelsArray` | Уровень играется в этой главе в указанном порядке | Без записи в `Levels` — ошибка при запуске |

### 6.1. Регистрация (обычно автоматическая)

- `Game/Create Level` и `Game/Content/Configure Remote Levels` регистрируют все `LevelData` под `Assets/` в группе `Levels`: адрес = имя ассета (существующий адрес сохраняется), метка `Level`, адреса и метки включены в каталог (`IncludeAddressInCatalog`, `IncludeLabelsInCatalog`), удалённые пути `Remote.BuildPath`/`Remote.LoadPath`, `PackSeparately`, кэш бандлов.
- Не переименовывайте ассет уровня после регистрации, не меняя адрес сознательно: ссылки `LevelReference` хранят строку адреса.
- Проверка: выберите группу `Levels` в окне **Window > Asset Management > Addressables > Groups** — уровень присутствует, адрес уникален, метка `Level`.

### 6.2. Каталог загрузки `LevelsData.Levels`

Файл: `Assets/Game/Levels/LevelsData.asset`, поле **Levels** (массив `LevelReference`, у каждого поле `LevelId` — выпадающий список адресов группы `Levels`).

- Добавьте **каждый** уровень, который встречается хотя бы в одной главе. Порядок в `Levels` не определяет порядок в главах, но индекс (позиция + 1) используется номером уровня в `Tutorials[].LevelNumber`.
- Пустой `Levels` — ошибка при старте: `The level catalog must contain at least one level.`
- Поля `LoopLevelCount`, `_randomizeLoopOrder`, `LoopStartLevel` относятся к легацийной прогрессии без глав и при настроенных главах не определяют порядок. `DownloadReserveCount` задаёт, сколько уровней держать скачанными заранее.

### 6.3. Если выпадающий список пуст

Надпись `No levels in 'Levels' group` — выполнить `Game/Content/Configure Remote Levels` и проверить Console.

## 7. Главы и награды

Поле **Chapters Array** (`ChaptersArray`) в `Assets/Game/Levels/LevelsData.asset`. Порядок элементов — порядок глав. После последней главы снова идёт первая (цикл).

Если `ChaptersArray` пуст, игра использует легацийную прогрессию (без улик/глав). Для проверки настроенных глав он должен быть непустым.

### 7.1. Поля главы (`ChapterData`)

| Поле | Обязательно | Назначение |
| --- | --- | --- |
| `LevelsArray` | Да, не пустой | Уровни главы в порядке прохождения. Каждый адрес должен быть в `LevelsData.Levels`. Каждый уровень даёт одну улику; размер главы = число уровней |
| `RewardsList` | Да (список не `null`; может быть пустым) | `RewardData`-ассеты, выдаются один раз на экране завершения главы (и снова в каждом новом цикле). Пустой список — экран наград не показывается |
| `LevelRewardsList` | Нет | Награды после каждого **не последнего** уровня главы. Пустой — экран наград пропускается. Последний уровень идёт сразу к виновному и наградам главы |
| `Title` | Нет | Название локации в HUD. Пусто — табличка скрыта |
| `CulpritPortrait` | Нет | Круглый портрет виновного. Пусто — вопросительный знак |
| `CulpritCaption` | Нет | Подпись раскрытия виновного |
| `CulpritSceneImage` | Нет | Картинка сцены виновного. Пусто — экран пропускается |
| `CulpritSceneCaption` | Нет | Подпись сцены |

Дополнительно в `LevelsData` (времена в секундах, ≥ 0): `EvidenceFlightDuration` (0.6), `AllEvidenceDuration` (2.2), `CulpritRevealDuration` (2.5, 0 = ждать нажатия), `SunburstTurnSeconds` (18, 0 = неподвижно). Менять только по решению дизайнера.

### 7.2. Награды

Тип `RewardData` — абстрактный ScriptableObject. Существующие подтипы (меню `Assets/Create/Game/Reward/...`):

- `CurrencyRewardData` (`Game/Reward/Currency`): валюта (`CurrencyKind`: `Gold`) и `Amount`.
- `BoosterRewardData` (`Game/Reward/Booster`): бустер (`BoosterKind`: `Growth`, `FreezeTimer`, `Compass`, `MagicWand`) и `Amount`.

Готовые ассеты: `Assets/Game/Boosters/Compas/BoosterRewardData.asset`, `Assets/Game/Boosters/FreezeTimer/FreezeTimerRewardData.asset`. Новые ассеты создавать только по решению геймдизайнера (тип и количество — его данные, не придумывать). Перетащите ассеты в `RewardsList` / `LevelRewardsList`.

### 7.3. Правила валидации (ошибки при старте)

- Глава с пустым `LevelsArray` или `RewardsList == null`: `Every chapter requires levels and a reward list.`
- Адрес главы не найден в `LevelsData.Levels` или пуст: `Chapter level address is missing from LevelsData.Levels.`
- Уровень главы без `MainImage` или `ClueImage`: `Every chapter level requires SearchData.MainImage and SearchData.ClueImage.`
- Сохранённый прогресс не соответствует главам (например, число найденных улик больше длины главы после сокращения главы): `Saved chapter progress does not match the chapter configuration.` — сбросить профиль (раздел 9.2).

## 8. Удалённый контент (Addressables Remote)

### 8.1. Существующие настройки (сохранять как есть)

`Assets/AddressableAssetsData/AddressableAssetSettings.asset`, профиль **Remote**:

- `ContentBranch` = `1.0` (текущее значение).
- `BuildTarget` = `[UnityEditor.EditorUserBuildSettings.activeBuildTarget]` (платформа активной цели сборки; в проекте есть каталог `Assets/AddressableAssetsData/Android`).
- `Remote.BuildPath` = `ServerData/[ContentBranch]/[BuildTarget]` (относительно корня проекта; например `ServerData/1.0/Android`).
- `Remote.LoadPath` = `https://sunstormstudio.com/RemoteContent/GlassMaster/[ContentBranch]/[BuildTarget]`.

Не заменяйте на localhost, не убирайте ветку/платформу, не меняйте значения без решения владельца. Изменение `ContentBranch` меняет и папку сборки, и URL — файлы и игра должны ссылаться на одну и ту же ветку.

### 8.2. Сборка

1. Убедитесь, что активная платформа (File > Build Profiles / Build Settings) — нужная.
2. Выполните **`Game/Content/Build Remote Levels`**. Метод вызывает `Configure` (делает профиль `Remote` активным, включает `BuildRemoteCatalog`, `DisableCatalogUpdateOnStartup`, регистрирует все `LevelData`, выносит общие зависимости в группу `Level Shared`), затем собирает контент. Ошибка сборки поднимается как исключение, в Console: `Remote level content build succeeded: <путь>` при успехе.
3. Результат (бандлы, каталог `catalog_*.json`/`.hash`) лежит в `ServerData/<ContentBranch>/<Platform>/`.

### 8.3. Размещение и доступность

- **Размещение файлов на сервер выполняет человек/внешний процесс.** Нужно скопировать всё содержимое `ServerData/<ContentBranch>/<Platform>/` по адресу `https://sunstormstudio.com/RemoteContent/GlassMaster/<ContentBranch>/<Platform>/`. Успешная сборка **не** доказывает, что файлы загружены и отдаются сервером. ИИ не должен утверждать, что контент доступен, без внешнего подтверждения (например, ответ 200 на URL бандла или каталога, полученный от человека).
- Каталог встроен в плеер, обновление каталога при старте отключено. Поэтому плеер, собранный до добавления уровня, не знает новых адресов: после добавления/изменения уровней нужно пересобрать контент **и** плеер (или согласовать другой способ доставки). Это следствие текущих настроек, а не рекомендация их менять.
- Сервер должен отдавать бандлы по HTTPS с теми же именами и хэшами, что получены в сборке; устаревшие файлы старой сборки не смешивать с новыми.

### 8.4. Локальная проверка vs удалённая доставка

| Проверка | Что подтверждает | Что НЕ подтверждает |
| --- | --- | --- |
| Play Mode в редакторе (режим Addressables Play Mode Script **Use Asset Database**) | Данные уровней, порядок, главы, UI-потоки | Работу сервера, скачивание, кэш |
| Успешный `Build Remote Levels` | Контент собирается, каталог создан | Загрузку на сервер, доступность URL |
| Play Mode с **Use Existing Build** / сборка плеера и запуск на устройстве, URL бандла открывается | Реальную удалённую доставку | — (требует внешнего размещения, выполнить вручную/получить подтверждение) |

Режим Play Mode Script выбирается в **Window > Asset Management > Addressables > Groups** (меню Play Mode Script). Для локальной проверки последовательности достаточно **Use Asset Database**.

## 9. Запуск в Play Mode

### 9.1. Подготовка

1. Нет ошибок компиляции; в Console нет красных ошибок конфигурации (раздел 12).
2. Все ассеты сохранены (`File > Save Project`, **Save Level** в окне уровня).
3. Откройте `Assets/Game/Main.unity` и нажмите Play. Сначала открывается окно предзагрузки, затем загружается уровень, играет фото-анимация Ready, затем начинается поиск.

### 9.2. Влияние сохранённого прогресса и безопасный старт с нужного состояния

Прогресс хранится в профиле игрока (`GameplayProgress`): номер цикла глав (`ChapterIteration`), число найденных улик текущей главы, ожидающая победа уровня, флаг получения награды главы. Незавершённый поиск не сохраняется. Игра **продолжает с сохранённого места**, а не с первого уровня. Если победа была сохранена как ожидающая, при старте сначала показывается результат (улика/глава), а не поиск.

Существующий безопасный способ начать с нужного состояния — меню проекта (не в Play Mode):

1. `Game/Profile/Show` — открыть папку профиля; **скопировать** файл профиля как резервную копию.
2. `Game/Profile/Delete` — сбросить прогресс (старт с первой главы, первого уровня). Также при необходимости `Game/PlayerPrefs/Delete`.
3. Чтобы начать с конкретного состояния, подготовьте `.json` профиля вместе с владельцем и примените через `Game/Profile/Apply From ...`. Не создавайте/не правьте профиль без данных; ИИ не знает нужного состояния — запросить.

Удаление профиля безвозвратно стирает прогресс и валюту; делайте только на тестовой машине после резервной копии и согласования.

### 9.3. Ожидаемая последовательность

1. Первый уровень первой главы (`ChaptersArray[0].LevelsArray[0]`). Фото-анимация Ready, затем поиск.
2. Найти все аномалии стадии (клик по рамке; промах — крест). Показываются маркер, звёзды, полёт в HUD; затем переход к следующей стадии (затемнение).
3. После последней находки — победа уровня; затем экран «You found the evidence!» (улика `ClueImage`, подпись `ClueName`); нажать **NEXT** — улика летит в слот. Продолжение **обязательно** подтверждается игроком (кнопка/касание); автоматического перехода нет.
4. Не последний уровень главы: при непустом `LevelRewardsList` показывается экран наград; затем загружается следующий уровень главы (по порядку `LevelsArray`).
5. Последний уровень главы: «You found all evidences!» → раскрытие виновного (если заданы портрет/подпись) → сцена виновного (если задана) → «Chapter complete!» с наградами `RewardsList` (если список не пуст). После продолжения номер цикла глав увеличивается, счётчик улик и флаг награды сбрасываются, стартует первый уровень следующей главы.
6. После последней главы начинается первая (по модулю числа глав); улики собираются заново, награды главы выдаются снова.

Награда главы выдаётся один раз за прохождение (защита от повторной выдачи); прогресс и баланс сохраняются в момент продолжения. Прерывание приложения посреди экрана результата восстановит показ результата при следующем запуске.

Для быстрого прохода в редакторе в проекте есть окно читов (`ForceWin` из `Assets/Game/UI/Windows/CheatsWindow/`); оно засчитывает победу, но **не заменяет** проверку реального поиска аномалий хотя бы на первом уровне.

## 10. Рабочий процесс ИИ (по шагам)

1. Прочитать раздел 0, зафиксировать текущее состояние `LevelsData.asset` и список `Level*.asset`.
2. Запросить недостающие данные (раздел 2). Не продолжать без изображений, порядка и границ глав.
3. Для каждого уровня по порядку: импорт спрайтов → `Game/Create Level` → заполнение полей → **Save Level** → закрыть и открыть заново, сверить значения → в Console и окне нет предупреждений (или они осознанно приняты и описаны).
4. `Game/Content/Configure Remote Levels`; проверить группу `Levels` (адреса, метка `Level`).
5. В `LevelsData.asset` добавить адреса в `Levels`, затем сформировать `ChaptersArray` (уровни, награды, при необходимости остальные поля). Сохранить ассет.
6. Сделать резервную копию профиля и сбросить его (раздел 9.2), если нужен чистый запуск.
7. Play Mode по разделу 9.3; зафиксировать в отчёте наблюдаемое по чек-листу.
8. Для удалённой доставки — `Build Remote Levels`, затем передать человеку список файлов и URL для загрузки и проверки (раздел 8).

## 12. Диагностика типичных ошибок

| Симптом / сообщение | Причина | Что сделать |
| --- | --- | --- |
| `The level catalog must contain at least one level.` | Пуст `LevelsData.Levels` | Добавить уровни в `Levels` |
| `Chapter level address is missing from LevelsData.Levels.` | Адрес главы не в каталоге или пуст | Добавить адрес в `Levels`, выбрать из списка |
| `Every chapter requires levels and a reward list.` | Глава без уровней или список наград `null` | Заполнить `LevelsArray`, инициализировать `RewardsList` |
| `Every chapter level requires SearchData.MainImage and SearchData.ClueImage.` | Нет основного изображения или улики | Назначить и сохранить |
| `Assign SearchData.MainImage before loading this anomaly level.` | `MainImage` пуст | Назначить |
| `Saved chapter progress does not match the chapter configuration.` | Профиль не соответствует новым главам | Резервная копия, `Game/Profile/Delete` |
| Игра стартует не с первого уровня | Сохранённый прогресс | Раздел 9.2 |
| Игра сразу показывает экран улики/главы | Ожидающая победа или завершённая глава в профиле | Продолжить показанный экран или сбросить профиль |
| Уровень не виден в списке `LevelReference` | Не в группе `Levels` | `Game/Content/Configure Remote Levels` |
| `requires a unique nonempty address` | Дубликат/пустой адрес Addressables | Сделать адрес уникальным, не дублировать `LevelData` |
| На стадии меньше аномалий, чем `Count` | Нет кандидатов без пересечений или ID исключены | Исправить `Bounds`/ID, разнести по стадиям, задать явные ID |
| Слот стадии пропущен (`slot omitted`) | Явный ID отсутствует/повторён/пересекается | Исправить ID или разнести аномалии |
| Нажатие по прозрачной области засчитывается / не засчитывается | Хит-область — весь `Bounds` | Подогнать `Bounds`/обрезать спрайт |
| Аномалии не пересекаются визуально, но не вместе в одной стадии | Касание разрешено, пересечение с площадью — нет | Проверить `Bounds` числами |
| Пустой выпадающий список `No levels in 'Levels' group` | Нет регистрации | Configure, проверить Console |
| Уровень не загружается в Play Mode | Режим Play Mode Script «Use Existing Build» без собранного контента или без доступного сервера | Переключить на «Use Asset Database» или собрать/разместить контент |
| `Build Remote Levels` падает | Не настроены `Remote.BuildPath`/`Remote.LoadPath` либо нет группы `Levels`/профиля `Remote` | Не заменять значения; сообщить владельцу, какие значения отсутствуют |
| Контент собран, но игра не качает бандлы | Файлы не загружены на сервер, неверные ветка/платформа в пути, старый каталог в плеере | Внешняя проверка URL, пересборка плеера |
| Награда не выдана или выдана повторно | Список `RewardsList` пуст, не тот ассет, прерванный цикл | Проверить списки; повторы допустимы только в новом цикле глав |

## 13. Чего не делать

- Не создавать производственные изображения, аномалии, уровни, главы и награды без решения геймдизайнера.
- Не менять игровой код и конфигурацию Addressables/профиля `Remote`, если задача не требует.
- Не удалять профиль игрока без резервной копии и согласования.
- Не заявлять, что контент доступен игрокам, на основании одной лишь успешной сборки.
